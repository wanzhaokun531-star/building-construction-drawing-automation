# 建筑施工图平面自动化分阶段实施方案

> 当前交付为实施方案，未开始插件开发。执行者须在用户明确允许实现后，按阶段逐项推进；届时使用 superpowers:subagent-driven-development 或 superpowers:executing-plans 跟踪任务与验收。本方案不授权创建代码工程、编译或运行测试插件。

**目标：** 将定稿方案DWG、参考制图资源、固定详图库和项目参数，转换为一份保留天正对象的施工图平面DWG、一份按图号合并的PDF，以及对应待确认清单。

**架构：** 以ObjectARX C++作为宿主插件，按实际天正版本设置对象适配层。先将真实图元提取为可追溯的建筑与标注数据，再由确定的规则、参数化节点和参考模板生成原生图元，完成排版、检查和宿主出图。

**技术范围：** 首版以当前AutoCAD 2020、Windows x64和实际加载的T20天正环境为验证对象；具体模块版本与编译组合在阶段0和1锁定。其他版本在形成单独验证结果前，不列入支持范围。

**需求基线：** [建筑施工图平面自动化需求基线](../specs/2026-10-28-建筑施工图平面自动化需求基线.md)。

## 实施原则

1. 先验证最关键的天正读写和保存能力，再扩展功能数量。
2. 首轮以用户提供的一层方案为样本，先形成可打开、可检查、可打印的完整小闭环，再扩展全部范围与多层。
3. 每一阶段都有实物交付和通过条件。具备部分读取能力、编译通过、保存成功和业务图纸合格分别记录。
4. 细节按阶段集中确认。窗台两端收头等未确认规则保持待定，不在当前继续逐条追问。
5. 缺参或冲突按照用户规则生成待确认提示；源方案和既定建筑尺寸保持不变。
6. 原生资源优先复用参考对象及依赖定义，结合经验证的天正接口修改允许的字段；不通过全图炸开实现保留天正对象的目标。
7. 首个样本跑通后固化规则和资源版本，避免每次开发重复读取、反复猜测同一份图纸。

## 技术路线与能力边界

### 推荐路线

采用ObjectARX C++主程序、天正对象适配、原生参考模板和规则计算相结合的路线。图层、文字、尺寸、轴号、标高及图框按对应类别引入参考资源；方案提供真实建筑数据，项目参数和固定详图库提供缺失构造依据。

天正适配优先采用厂商支持的接口。若部分类型可通过原生克隆和公开属性稳定处理，也须逐类证明修改后仍保留类型、关联和正确显示。现有ObjectDBX提取用于分析，生产流程不依赖Python脚本作为插件业务主程序。

另一个可评估路径是由C++调用经验证的天正自动化或命令接口。它可以作为个别对象的适配办法，但需要核实版本、参数、交互和失败恢复条件；有提示框、屏幕坐标或不可控命令状态的调用不作为整套一键流程的基础。

如果必要类型无法可靠创建、编辑或保存，应先取得厂商接口支持。经用户另行确认，可先交付保留原有天正构件、补充已验证标注的受限版本。受限版本不得算作全部功能完成。

## 运行流程

日常使用按“选择定稿方案、确认项目参数和资源、执行生成、查看成果及待确认清单”组织。首次项目设置和制图资源准备不要求每次重新完成。

内部依次执行：输入与依赖预检、提取建筑数据、规则与参数检查、生成构件和标注、避让排版、图框出图、另存DWG及合并PDF、形成检查清单。各步骤保留来源和状态，便于从清单定位到图面。

只读分析文件不直接充当最终数据合同。正式开发时需要定义对象类别、坐标、单位、几何、宿主关系、楼层或区域、参数来源、模板版本及待确认状态。跨图对象关系在目标数据库内重新解析，不能直接复用旧图的对象ID或隐含坐标。

## 阶段总览

| 阶段 | 主要成果 | 进入下一阶段的条件 |
|---|---|---|
| 0 基线和资源准备 | 样本、测量表、资源清单、能力验证任务单 | 模型单位及验证对象明确，资源缺口分级 |
| 1 天正及宿主能力验证 | 最小ARX探针、对象能力矩阵、重开和出图证据 | 首轮所需类型能够可靠读写、保存和重开 |
| 2 第一张基础样图 | 轴网、外围三道尺寸、基础文字、图框、单页DWG/PDF | 几何与样式正确，用户完成首图对照 |
| 3 既有构件及通用标注 | 内部尺寸、门窗号、通用说明、标高、坡向、剖切、索引能力 | 当前已有构件及标准测试对象通过，未知项明确标识 |
| 4 构造实体及关联标注 | 排水、台阶门廊、门槛窗台等实体与对应标注 | 参数、实体、计算和标注一起核对，全量覆盖清单完成 |
| 5 整图排版避让 | 稳定的各类标注协调及人工复核入口 | 遵守固定侧、区域、成组移动等限制 |
| 6 多层及正式出图 | 同项目一个DWG、按图号合并的多页PDF | 图框升级、纸幅比例、字体线宽、页序核验通过 |
| 7 回归与交付 | 发布包、资源、说明、样例和验收报告 | 支持范围内的功能、图面和保存验证全部通过 |

阶段0、1决定总体可行性。阶段2形成第一版可用样图。阶段3至6完成用户确认的全部范围，阶段7决定正式交付范围。第一版样图通过不等于全部施工图功能完成。

## 阶段0 基线和制图资源准备

### 工作任务

- [ ] 复用现有两份JSON、原DWG和讨论基线，核对提取结果与当前文件的对应关系。
- [ ] 在源文件可正常读取时记录指纹并建立测试副本，原文件保持只读使用；源文件占用时等待可读条件，不关闭用户CAD或强行覆盖。
- [ ] 核实模型单位、坐标基准、嵌套块变换和楼层范围，以实际几何为依据。
- [ ] 提取完整图层、线型及比例、文字真实字体、标注样式和对象局部覆盖，核实天正基本设置对显示的影响。
- [ ] 按类别建立参考对象样例和纸面测量表，包括轴号、短轴线、尺寸道间距、字高、符号、图名及图框。
- [ ] 编制原方案对象处理表，区分保留建筑对象、样式转换的标注、需要替换的旧图框或说明；交用户集中核对。
- [ ] 收集或列明字体、CTB/STB、参考出图PDF、固定详图库、A2/A1图框和项目参数缺口。

### 交付与验收

交付输入基线、对象分类清单、资源清单、测量表、参数字典和原图处理表。每个关键测量值应能指回参考对象或明确说明；沟深等竖向值须有可靠依据。顶层包围盒不能代替尺寸线坐标、墙中心线或构造深度。

现有属性提取已经完成一部分工作；完整尺寸定义、实际关联、字体和实测仍需补齐。CTB缺失可以列为后续出图依赖，但模型单位和首轮样本的真实几何必须先明确。

## 阶段1 天正和宿主能力验证

本阶段在用户允许实现后才编写验证代码，目的在于尽早证明主路线可行。

### 工作任务

- [ ] 锁定AutoCAD、ObjectARX、编译器及天正实际版本，完成最小ARX编译、加载和卸载。
- [ ] 对墙、普通门窗、组合门窗、文字、尺寸、轴号、标高、楼梯、剖切、引线等建立能力矩阵，分别记录读取、创建或克隆、修改、关联、保存和重开的支持情况。
- [ ] 首先验证阶段2所需类型，其余类型在进入所属模块前完成验证。
- [ ] 对每种支持类型执行“读入副本—修改允许字段或创建样例—另存新DWG—关闭重开—回读并检查显示”。
- [ ] 验证跨图克隆后样式依赖、文字属性及墙门窗、尺寸等关联关系，检查失败回滚和源文件不变。
- [ ] 验证宿主原生PDF设备、可用纸张标识和单页输出；尽早试验不同纸幅的多页输出路径。

### 交付与验收

交付最小ARX、版本记录、能力矩阵、读写前后表、新DWG、重开截图和试出PDF。通过条件包括天正对象类型仍正确、几何和文字符合预期、关联保留、显示可编辑。只有对象数相等或保存调用成功，不算通过。

### 未通过时的处理

停止扩展依赖该能力的功能，先查明接口、版本或授权条件，必要时取得天正厂商支持。不通过便不能承诺该对象的完整自动生成；不以炸开、猜写私有数据或屏幕操作掩盖缺口。其他独立只读工作和资源整理可继续。

## 阶段2 第一张基础施工图样图

### 工作任务

- [ ] 建立一次生成的工作副本和成果数据库，保留原建筑内容，按阶段0处理表转换原标注，避免新旧内容重复。
- [ ] 完成样本中的墙、柱、房间和门窗识别，按真实几何提取中线和洞口；200厚主要墙候选与局部短墙排除需要可追溯依据。
- [ ] 生成正交轴网、编号、外侧短轴线，以及四侧三道尺寸。
- [ ] 生成房间名、已具备完整编码规则的普通门窗编号、图名及原方案面积文字。
- [ ] 套用A3横向1:100图框，输出一张基础施工图DWG、单页PDF及待确认清单。

### 交付与验收

用提供的一层方案形成可实际打开检查的样图。逐项对照外墙、内院、100厚隔墙、门垛、洞口及总尺寸范围；验证未改变方案实际尺寸。图层、文字、轴号和尺寸形式与对应参考类别对照。

不确定轴线不能静默猜定；非整百编码规则不完整的项可以待确认。PDF可先作为页面路径验证，字体或打印样式未齐时保留其验收缺口，不宣称纸面线宽一致。

## 阶段3 既有构件标注及通用标注能力

本阶段在方案已有构件及标准测试对象上完成通用标注能力。新增构造的最终尺寸、说明、标高坡向和索引随阶段4对应实体一起生成、验收。

### 工作任务

- [ ] 补齐内部净尺寸、隔墙定位、凹凸局部尺寸、庭院净尺寸和轴间尺寸。
- [ ] 完成楼梯集中踏步说明、特殊踏步和厨卫固定设施的定位尺寸。
- [ ] 完成门连窗分段识别、全部门窗编号及固定侧、旋转和引线规则；编码表覆盖宽高同时非整百等边界后再泛化。
- [ ] 完成房间名、普通及构造说明模板、标高、坡向、穿过楼梯的剖切和详图索引。
- [ ] 建立图面待确认标记与清单之间的对应关系，包含位置、来源、缺项或冲突原因。

### 交付与验收

交付既有构件标注样图、通用标注模块和规则覆盖表。每类尺寸保留取点和实际数值依据，门窗编码能够回溯洞口尺寸，说明模板使用的参数可查，索引对应真实图库图号。新增构造尚未生成的关联标注在覆盖表中明确转入阶段4，不计作已完成。

测试内容至少覆盖：100厚隔墙、非规则房间、组合门窗、镜像或旋转块、非整百尺寸、缺参和原文字矛盾。未知目标图号不得冒用参考项目的图号。

## 阶段4 构造实体参数计算及关联标注

按四组模块交付，每组先做一个典型节点并验证，再扩展同类：

| 模块 | 具体任务 | 重点验收 |
|---|---|---|
| 台阶与门廊 | 按方案完成面高差和高度范围取级，参考踏步宽、平台边界，按D=P＋（N－1）×b生成 | 平台承接最后一级踏面，已定门廊边界不变，空间不足明确提示 |
| 散水与明沟 | 外墙及庭院外墙布置、齐边中断、墙→散水→明沟、上游控制断面和出口校核 | 采用对应室外标高，沿实际路径计算，缺坡度或接入参数不输出假数值 |
| 门槛与窗台 | 按门窗分段及固定节点生成，区分内外窗台、门槛顶和窗台顶，控制找坡及滴水 | FDM默认只门段设门槛，外挑与滴水距墙按最终完成面，未确认两端收头保留待定 |
| 其他构造与专业部件 | 管井、洞口、空调机位及相关立管，按补充的具体依据和节点接入 | 位置、规格和适用条件可追溯；当前未讨论的布置依据须先补齐 |

### 工作任务

- [ ] 把固定详图库整理为“适用条件、原生对象或图形模板、可替换参数、控制基准、目标图号”的映射。
- [ ] 确认库内哪些节点仅用于索引，哪些需要参数化后用于平面构造生成，逐类验收其表达。
- [ ] 区分用户参数、方案数据、参考实测和推导值，关联计算后记录结果与校核状态。
- [ ] 每个构造模块同时调用阶段3的标注能力，交付该模块的尺寸、说明、标高坡向及详图索引，并核对它们与实体、参数和计算结果的关联。
- [ ] 明沟按已确认优先级处理冲突；其他构造引用其已确认规则，不能自动把明沟的调整顺序推广成全部构造规则。
- [ ] 对缺参、规则未确认、输入矛盾和能力不支持分别分类，图面按待确认机制表达。
- [ ] 阶段4结束时执行一次全量构件与标注覆盖核验，检查原有对象、全部新增构造及待确认项，再进入阶段5。

### 交付与验收

交付构造模板包、参数表、计算核对表、包含关联标注的构造样图、全量覆盖表及未完成项。直线台阶验算级数与进深，排水段验算起终点和转角连续性，门窗节点核对平面边界、标高、构造层偏移和适用条件，同时确认其尺寸、说明和索引无漏项。

库中没有可确认做法时保留待确认；不能凭“模板已接入”认定复杂节点都能自动生成。尚不支持的必需模块保持未完成状态，不能从最终范围中静默删除。

## 阶段5 全图避让和排版

### 工作任务

- [ ] 汇总房间名、门窗号、尺寸、轴号、标高、坡向、索引和说明的局部规则，提出一套全图处理次序，使用样图区集中确认。
- [ ] 实施文字沿线移动、线外引线、三道尺寸成组外移、轴号同步及局部尺寸调整。
- [ ] 保持门窗编号默认侧，索引仅在同一区域内自动换侧，房间名留在所属房间；跨区域移动转人工确认。
- [ ] 以参考测得的纸面字高、符号和净距建立碰撞范围，处理长文字及换行。
- [ ] 设置有限的搜索区域和终止条件，无法解决时保留标注并列清单，避免反复相互推移。
- [ ] 以图框服务提供的有效绘图区为约束，支持纸幅变化后的重新排布；最终页面范围随阶段6一起验收。

### 交付与验收

交付密集标注场景、处理前后对照和剩余冲突清单。确认未通过缩小字高、改变尺寸数值或移动建筑构件来排开图面。

全图次序属于本方案后续需确认的设计项；已确认的固定侧、区域边界、三道尺寸联动和人工确认限制必须始终满足。

## 阶段6 多层图框与DWG及PDF出图

### 工作任务

- [ ] 按确认的输入范围识别各层，统一放入一份施工图DWG；每层独立图框，楼层与图号对应可查。
- [ ] 生成图名、比例、面积组及图框字段，面积沿用原方案，不重算。
- [ ] 以A3横向1:100为默认，按A3、A2、A1升级，使用经确认的大规格图框。
- [ ] 纸幅或图框有效区域变化后重新调用阶段5排版，复核尺寸组、轴号、索引和说明的位置。
- [ ] 锁定PDF设备、纸张标识、打印窗口、比例、字体与CTB/STB，检查每页纸幅及线宽。
- [ ] 每框一页，按图号合并为一个PDF，并核对页数、顺序及不同纸幅。
- [ ] 输出同项目DWG、PDF及检查清单，记录资源、规则和环境版本。

### 交付与验收

DWG关闭重开后图框、天正实体、关联、文字及图层仍正确。PDF逐页检查纸幅、比例、字体、线宽、页面范围、图号和页序；不能只验证PDF文件存在。

超过A1仍容纳不了时保留DWG内容、列人工处理项，不自动裁掉内容或改变已定比例。该页的出图完成状态及处理结果须单独核对。CTB、字体或关键页面配置未齐时，最终打印一致性尚未验收。

## 阶段7 回归验收和交付

### 工作任务

- [ ] 在已锁定宿主及天正环境完成典型项目回归，包含正交、凹凸、内院、多个出入口、多层、组合门窗、镜像块和密集标注。
- [ ] 覆盖缺参、参数冲突、同名样式不同定义、字体缺失、对象能力不支持、保存失败及图框溢出。
- [ ] 对源文件、输出和依赖记录指纹；记录本次ARX及资源版本对应的验证结果。
- [ ] 测量典型样本耗时，确定可支持的图纸规模及性能基线，再提出优化任务。
- [ ] 打包ARX、源码和构建说明、规则和模板资源、参数填表说明、操作说明、验收DWG/PDF及检查报告。

### 最终通过条件

1. 定稿方案的建筑内容及实际尺寸保持正确，原文件未被写入。
2. 支持范围内必需天正类型可生成、另存、重开并保持正确类型和关联。
3. 已确认制图属性与参考一致，几何内容与项目参数有依据。
4. 全部已确认功能有对应测试与样图；未支持功能、缺失资料和待确认项明确列出。
5. 一个项目DWG和按图号合并的多页PDF均通过实际打开、图面及打印检查。
6. 首张全功能样图经用户对照确认后，才扩展批量应用范围。

带待确认提示的阶段成果可用于继续核对；关键资料未齐时，不将其记作全部业务验收通过。
