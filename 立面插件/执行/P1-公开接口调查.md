# P1：TCH 业务值公开接口只读调查

调查日期：2026-11-01。范围为 AutoCAD2020/ObjectARX23.1、已安装 TArchT20V8，以及 Autodesk/天正官方资料。本轮仅新增本报告；没有修改 N1 final 的源码、构建、驱动、公共 NativeEvidence，未启动 CAD、发命令、写 DWG 或联络厂商。

## 结论

**没有找到可直接编译调用、且公开文档明确支持本机 TCH 标高值、图名、轴号、索引编号修改的天正 C++ SDK/头文件/导入库或正式 setter。该结论是“本轮所查来源未找到”，不等于接口不存在，也不等于所有接口已经穷尽。**

**公开的 Y 向 grip 确实有一个值得单独验证的入口，但目前没有证据证明它能修改该样本的标高值。** ObjectARX 公共接口允许调用 getGripPoints 后按实际返回索引执行 moveGripPointsAt，业务副作用由该自定义实体的实现决定；天正随产品帮助又明确存在某些标高随位置动态更新的模式。二者只能支持“实施一个隔离对照试验”的决定，不能直接推导“Y 向 grip 就是标高 setter”。当前 N1 只试 X 平移，既没有验证也没有否定这条路径。

当前实际原生根类名是 **TDbSymbElevation**。没有在本机2020SDK找到 TDbElevation 的声明；本文不把后者当成已确认的可链接 C++ 类型。不要为符合口头名称自行声明或 cast 一个猜测的厂商类。

## 3. 现有实测证据不能被过度解释

只读复查现有 `阶段1/runs/elevation-native-20261101-173718-2a38f8b4/case/prototype-4.json`（round1旧候选的记录，不冒充当前final运行）：

- 绑定参考中的标高根10838，实际根类 TDbSymbElevation；递归公开表示包含一个实际 AcDbText，内容 `2.800`。这提供了下一步试验的**显示值 getter**。
- 其实际返回5个grip，其中两个坐标相同。相同坐标不能证明语义相同，不能只按坐标去重后漏测某个公开索引。
- 根对象 AcDbText/MText/MLeader cast 均失败；不能直接调用这些标准类 setter 来改根。
- `AcDbAssocValueProviderPE` 查询实际为 true，不能说没有该协议；但协议所需 valueName 未取得。默认/提升 RX 各45个成员，owner仅为 AcDbEntity/AcDbObject/AcRxObject，collection 未遍历且 complete=false。**这不是“全部接口穷尽”证明，也不授权猜 Elevation/Value/空字符串等值名。**
- 当前 N1 的 X 平移与保存复读只说明指定刚体操作的公开观测保持，不能用它得出 Y 移动、Y grip 或动态状态下数值更新的正反结论。

旧 `NativeElevationRoundTripProbe.inc` 的 core 明确仅 X 平移，注释也没有声称 +0.123/−0.123 数值往返完成。其他旧业务/UI桥路线不纳入本次可用 C++ 入口。

## 4. 可提出的最小隔离探针（设计，尚未实施）

可以提出 **ElevationYGripObservation**，仅检验公开位置编辑是否在该安装/该模式下改变标高的实际显示值。其依据是本机2020公开夹点协议和随产品的动态位置更新说明；它不是已经发现的业务 setter，也不能扩展到图名/轴号/索引改号。

1. 新会话、新模块、新命令和新输出目录，继续只读 SideDB 源、SHA绑定、零代理、源 kForRead、目标独立库、映射/所有权检查。不要改正在验证的 N1 final，不复用其宿主或覆写输出。
2. 使用绑定参考中10838仅作为本次夹具定位，先取得实际 Text `2.800`、完整有界公开观测、所有5个grip、stretch、资源定义。未知TDbMText占位保留，不能充当数值或字形。
3. **不切换动态标注状态，不猜未公开系统变量名，不调用天正命令。** 若无法通过正式公开接口确定当前状态，报告 `dynamicAnnotationState=unknown`，试验结论只对该记录的宿主/状态成立。没有变化不等于所有动态状态都不支持。
4. 每个分支从同一源重新克隆到独立新库，避免某个失败恢复污染后续分支：A为零操作控制；B为 `transformBy(translation(0,+123,0))`；C0–C4分别 `getGripPoints` 实时返回索引0–4后，仅该索引 `moveGripPointsAt(indices,(0,+123,0))`。索引来自该次公开返回，**不预称某索引是“数值夹点”**。这是有界公共协议试验，不是猜私字段。B和C的区别必须单列：UI MOVE的动态更新说明没有承诺直接 transformBy 或 grip 调用有完全相同通知语义。
5. 每步前flush checkpoint；每步后读源公开指纹与文件SHA；读目标实际 Text/MText、几何/所有夹点。分类为“仅位置改变”“实际显示数值变化”“不支持/返回错误”“公开值不可读”，不能只用 eOk 作为业务改值成功。
6. 明确 getter：遍历安全的公开 explode，只有实际 AcDbText::textString(AcString&) 或 AcDbMText::contents/text 成功取得的内容才记录；跟踪原来承载 `2.800` 的实际节点类型/路径，并保留所有其他文字。不修改展开得到的瞬态文字。可另外调用根公开 list() 作辅助业务文本输出，但只有实际输出并核对的字段才能使用，不能把计划中的字段当成已存在 getter。
7. 若某分支确实改变显示值，再对同类新clone试 +246 及负向位移，核实际响应是否一致，并做−123恢复。不要仅因图面Y为123就填预期值2.923：必须先确认模型单位、标高显示单位、符号模式及换算，才可给出数值预期；若只能读显示文字，则结论限定为显示内容变化，不能宣称独立内部标高 getter。
8. 对发生变化的分支和恢复分支分别保存**新文件**、关闭输入、独立新库重开；只用该文件已保存目标句柄查找，核根类型/owner/nonproxy、实际显示文字、几何、资源和源保护。任何所有权异常、意外getter/C++异常为硬失败；已知空公开表示继续作为限制。

只有上述实际往返成功，才能写“在记录的模式与状态下，指定公开grip/Y变换使可观察标高显示值改变并保存”。要成为生产 `setElevation(desiredValue)` 仍需证明：单位/零点和所有符号模式、状态可控、独立目标值可达、以及最终符号位置是否保持。**若改值必然伴随Y位移、反向恢复又把数值改回，仍不能解决要求固定位置下任意赋值的问题。**

对图名、轴号、索引，本轮没有找到同等强度的公开数值/字符串改写协议依据，暂不设计通过移动来“输入任意编号”的试验。厂商正式SDK、实际公开业务属性或经过文档绑定的值名出现前，继续记未找到可调用 setter；不使用 EntMod/DXF组1、私有filer、未知导出、COM/CUA或天正业务命令兜底。
