## 最小修改与边界

`tools/watch_native_case.py`、`tools/watch_command_case.py` 仅修改同一处 `observed.update`：

```python
normalQuit = (final['nativeQuitConfirmed'] and not final['forcedTermination']
              and not stop_needed and final.get('workerExitCode') == 0)
explicitStopRequested = stop_needed
normalQuitUnprovenDueToExplicitStop = stop_needed
```

正常退出必须同时具备 QUIT 标记、无 supervisor 强停标记、无 watcher 显式停止请求以及实际退出码 0。缺退出码、退出码 70 或显式停止请求均保守判为未证明正常退出。

`forcedTermination`、`timedOut` 仍复制 raw final 原值。停止请求本身不证明强停真的发生，因此没有把 `stop_needed` 写成 `forcedTermination=true`。本历史案例的实际强停结论另由匹配 nonce/PID 的 stop 原始记录支持。新增字段中的“未证明”不等于无条件断言异常终止。

补充授权涉及 `阶段1/工具/retire_reader_staging.py`、`tools/retire_command_staging.py`：仅在原 `report=dict(...)` 的 `normalQuit` 增加 `final.get('workerExitCode') == 0` 和 `not any(session.glob('isolation-stop-*.json'))`，另加 `explicitStopEvidencePresent` 记录该文件名存在条件。只检查本会话目录的 stop 文件名，不读取内容，不据此声称强停确实发生；存在这样的文件就保守视为正常退出未获证明。停止记录内容的 nonce/PID 归属核对仅在本次历史 correction audit 中完成。

没有改 CAD 启停、超时、队列、业务 status、retirement 的清理/权限/路径/哈希校验和操作、common NativeEvidence、native_case_host 或共享宿主流程。四份修改前脚本已逐字节封存，可审查旧 binding 指向的旧 SHA。AST 比较确认只改变 `normalQuit` 和新增证据字段，其余语法结构相同；retirement 源文件仅通过精确字节片段替换修改该表达式。业务 `nativeStatus=failed` 保持，不重判业务通过。未来新 binding 应由既有 prepare 流程绑定更新后的 helper SHA，不改历史 binding。

命令从工作区根运行：

```powershell

```

测试通过 AST 隔离执行实际 watcher 的证据聚合表达式，不导入 watcher、不执行主流程或任何启动/停止 helper。期望来自原始 stop 和手工定义的控制条件，未复制生产公式作为期望。

1. 原公式：4 个测试，6 个子断言失败，exit 1，记录 `red-output.txt`、`red-exit-code.txt`。真实 fallback 在两个 watcher 均复现 `True is not false`。初次试写测试曾因新增字段尚不存在报 KeyError；调整断言为缺字段即明确失败后得到此正式 RED。
2. 加显式请求门禁：4 个测试通过，exit 0，记录 `green-output.txt`。此时尚未满足后续补充的退出码条件，不作最终结论。
3. 增加真实 exit70 且请求标志为 false、缺退出码两个反例：6 个测试、4 个子断言失败，exit 1，记录 `exitcode-red-output.txt`。
4. 加 `workerExitCode == 0`：6 个测试全部通过，exit 0，记录 `final-green-output.txt`、`final-green-exit-code.txt`。
5. 补充两个 retirement 的真实 exit70、缺退出码、exit0 正控制、exit0 但本会话存在 stop 记录：8 个测试，10 个子断言失败，exit 1，记录 `retirement-red-output.txt`。
6. 两个 retirement 同步修正后：**8 个测试全部通过，exit 0**，记录 `four-file-green-output.txt`、`four-file-green-exit-code.txt`。测试覆盖四个生产脚本的真实聚合表达式。

最终覆盖：真实 fallback；真实 exit70 即使丢失 stop 标志；缺退出码；无 fallback/有标记/exit0 的正常控制；请求存在但没有强停证据时不得虚构强停；原有负证据和 raw 值保持。正常控制为**合成 Python 控制输入**，不能当作新 CAD 原生成功证据。
