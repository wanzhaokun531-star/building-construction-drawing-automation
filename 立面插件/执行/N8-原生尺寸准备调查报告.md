## 结论与下一步

建议先做 **N8a 独立原生 feasibility probe**，再写生产 adapter。边界是：从项目真实站点生成一个整体 TDbDimension2，使用公开 definition/grips 建立动态节点映射，验证端点及全部中间点、非整百、大坐标、横竖转换、比例和单位。它是 Task4 必要增量，不重跑“原型原样克隆后恢复”作为生成验收。

最小生产方向是新增独占新库的 `PreparedDimensionBatch`；失败整库销毁，不接收借用目标库。现有 `PreparedBatch` 仍只有 Line，`InPlaceWriter` 仍只接受未变的单 Line，不能把尺寸塞入后调用既有提交器。N8a 不写生产服务、不接当前图、不改 M2/N2/N6 契约。公开节点适配可以独立推进，缺配套平面或天正 SDK 不构成所有尺寸工作阻塞。

最小 `DimensionPlacement` 应包含链键 `(viewIdentity, featureIdentity, purpose)`、family/类别、laneIndex、显式单位法向 n、基线参考点/支持线及确认来源、逐站实际锚点选择或明确的派生测量线政策。基线可由 `supportPoint + n * layout.laneOffsetsInput[lane]` 表示，沿链方向的位置无关；需要同时核 lane 合法、n 与链方向正交。所有点处于同一已声明输入坐标系，第一版明确 XY/WCS、Z=0，不能从屏幕/UCS 猜。

## N8a：明确输入和操作边界

建议保留独立测试驱动，调用同一个待实现 `adaptChainOnOwnedDb(request)`，所有副作用仅在驱动/服务自建 side database。不传 ambient/当前文档作目标。源原型只读，测试句柄只用作 SHA 绑定 fixture 查找。1/2/6/12 是覆盖点，绝不是产品段数上限；选型必须按实际公开段数和经核准类别，找不到适配种子返回 `DIMENSION_SEED_NOT_FOUND`，不能拼成普通块、Group 或 N 个独立尺寸。

第一条有意义的生成夹具建议使用已验证 2 段竖向原型，mm、1:100、保持原朝向/纸面样式：

- 项目方向 d=(0,1)，三实际共线测点 `(50000.125,70000.25)`、`(50000.125,71234.625)`、`(50000.125,73333.375)`；站距 1234.375、2098.75 mm，零位小数显示为 `1234`、`2099`。
- 显式基线 x=48500.125，测点/基线均为测试输入事实，不能从参考坐标推导项目高度。
- 准备后仅一个 TDbDimension2 模型根、非 proxy、owner/database 正确，三节点与两段完整匹配，公开显示与上值匹配；不能只断言长度不等于参考值。
- 在已生成对象的共享测站沿 d 移 +17.125，再恢复；分别观察相邻段 +17.125/−17.125、其它字段按合同保持、重读节点位置和显示，恢复后再次全字段比对。
- 基线法向移一段明确非整百距离，再恢复；全部实测端点保持、每段 dimLinePoint 随动、测值保持。
- 保存生成态到新文件，独立新数据库重开，用生成文件自身句柄/清单查对象，核全部字段。不能保存恢复后的参考原型冒充生成态。

比例候选变换系数为 `k=(目标比例分母/源比例分母) * (源mmPerUnit/目标mmPerUnit)`，只用于参考外观的初始物理比例换算，随后尺寸节点必须回到真实项目站点。此式不是 TCH 支持该变换的证明，更不能代替单位显示因子的适配。m 1:50 若实际文字是 `1`/`2` 或其它错误值，应记录失败/partial，不能改写显示串或修改 explode 出来的临时标准尺寸骗过断言。只有公开 root 接口或经验证适配原型可解决；没有入口就保留该能力缺项。

上述 N8a 范围合理：它围绕同一条公开 grip 适配机制，能直接决定生产 adapter 边界。最终可以 overall partial，但每个场景必须有自己的实际输入、API状态、观测、失败点；基础共线生成失败时不能用未执行的比例场景冒称已验证。

## 节点语义与不交叉更新

1. 对 clone 做只读 `explode`，读取标准 aligned/rotated dimension 的 xLine1Point/xLine2Point/dimLinePoint、measurement、dimensionText、formatMeasurement 和有效样式。TCH 本体仍保留整体实体；临时展开物只观测、按真实所有权回收，绝不入库替代或修改它们影响父对象。初版可只支持已经实证的 aligned 分段；遇另一类型详细诊断或另做明确适配。
2. 以端点几何和邻接建立完整路径，不依赖 explode 顺序或端点方向。N 段应对应 N+1 唯一节点、两个度1端点、其余度2、连通无分支；按目标 d 的局部投影排序确认每条边连接相邻站。用局部差值与明确数值误差界匹配，保留原坐标，不能用容差“合并”项目真实短段。匹配误差需小于最小站距的可分辨边界。
3. 每个测量节点与本次 `getGripPoints` 返回值匹配；一对一且无歧义才使用这个临时 index。基线候选从各段 dimLinePoint 所在共同基线推导、排除测量端点，再用公开移动后的联动观测验证。文字/界线尾端 grip 不凭位置序号当测站。
4. 对齐朝向及共同测量线后，在同一个沿向坐标系记旧站 q[i] 和目标 t[i]，二者均严格递增。先将 t[i]<q[i] 的节点按 i 升序移动，再将 t[i]>q[i] 的节点按 i 降序移动。这样每次移动都落在已更新或尚未移动的两邻站之间；不需要临时极大坐标，也不因先动左端而穿过右端。例 q=[0,100,200]→t=[150,250,350] 必须从右端开始。
5. 每一次移动前重新读取 definitions/grips，按路径节点语义匹配当前 index；移动后立刻重读所有节点/段，确认仅预期沿向变化、路径未重排、段数不变、测值对应邻接变化。绝不缓存上一轮 index。公开实现如果带来额外联动，应在实际观测层失败，不能“修正预期”掩盖。
6. 测站最终成立后再定基线，并核实际锚点、基线、段值及显示。非共线锚点不能直接套上述共线证明；原生 aligned 分段可能改成斜距，这正是单列小试的原因。整对象旋转/缩放也要重新观测，而非把数学矩阵成功当原生语义正确。

`PrototypeProbe.cpp:904–932` 已有公开分段读和旧式 index grip 调用；`:1042–1112` 证明基线及**一个**共享点往返，未证明端点/全部节点重设。`N1ProbePolicy.h:27` 的 find_shared 只返回首个可匹配相邻点，不是完整链图构建器。`:1022` 的固定句柄集合仅是测试夹具，不能移入产品类别决策。

```cpp

// PreparedDimensionBatch: move-only；独占新库；roots + 公共观测 + source绑定
```

seed 的 handle 仅作与文件SHA绑定的物理对象定位；选择依据仍是经批准类别、实际分段和适配版本。参考从锁定/核SHA的磁盘字节加载独立只读库，不从恰好同名、可能有未保存编辑的借用数据库克隆依赖；可参考 `NativeMaterials.cpp:66–81` 的边界，不修改该实现。

新库由服务创建，检查非文档库、非源/ambient；RAII切换workingDatabase只在必要公开操作时，异常也恢复。所有 opened 对象先 close，再销毁库；未入库的瞬态才 delete。clone 已入库对象不能交给默认 delete 智能指针。mapping、根IDs及观察数据必须依附owner寿命，不能返回借用指针跨事务/库销毁。禁止通过“empty target”借口接收任意调用者目标库，空模型不代表资源/未保存编辑为空。

失败后丢弃整库，包括已经成功克隆的前几条链/资源；成功最后一步才发布结果。不可用 `abortTransaction` 假设 wblock 副作用全部回滚。M2已有同类新库设计及实际失败证据，`NativeMaterialTiles.h:13–31`、`.cpp:367–376`、`:435–445` 可作依据，但其 root 仅 Hatch、资源白名单也不含全部 dimension/style 依赖，不能直接调用其 Graph/TCH filer 或并发改它。
