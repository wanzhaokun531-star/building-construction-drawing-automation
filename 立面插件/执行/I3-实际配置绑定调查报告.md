### 资源及外部字体的相关性

直接从 Line/AlignedDimension 定义点读取 WCS 数值，或保存用户明确输入的 WCS 窗口，不以字体字节为依赖；标题/说明按 SDK 原始字符串和显式用户关联核对，也不需证明文字墨迹范围。不要为此有限能力先强制冷字体/字形全验。

如果以后用文字实际墨迹 bounds 自动分区、判断遮挡、生成并排布标签或保护文字可见外观，TextStyle 定义、实际解析字体及 bigfont/替代字体、实际文件内容和解析环境就相关；同路径同文件名不足以发现字体替换。SceneReader 的 style 签名只有文件名及样式参数，没有外部字节。完整生成还涉及 DimStyle→TextStyle/箭头块、Linetype→shape/font、Hatch 的 pattern/边界和其它引用闭包，不能用三类资源表名册代替。字体文件不存在、无法确定替代来源应报告所影响用途的缺口，不伪填 sentinel。

可对 **exact SDK 类** 使用公开 typed getters，或公开 `AcDbObject::dxfOut`/`AcDbDxfFiler` 收集有类型有组码的完整输出，作为后续完整公共状态适配路径。已核本地实际 2020 头文件 [dbmain.h:1767](C:/Autodesk/ObjectARX_for_AutoCAD_2020_Win_64_bit/inc/dbmain.h:1767)、[dbfiler.h:301](C:/Autodesk/ObjectARX_for_AutoCAD_2020_Win_64_bit/inc/dbfiler.h:301)：dxfOut 有 `bAllXdata`/regAppIds 参数；filer 有明确 database、version、typed write 接口。实现需保留有意义的字段/数组顺序，归一到源库引用身份，检查 filer status，明确 XData/扩展字典及引用资源覆盖；成功输出一段 DXF 不等于已取得全部依赖闭包或运行时字形资格。

Autodesk 2020 的 [DWG/DXF 存储合同](https://help.autodesk.com/cloudhelp/2020/ENU/OARX-IOP/files/GUID-99626F3A-2EAE-42DA-9AC3-009D9E319AD6.htm)说明存储表示需足以恢复对象状态，同时允许应用不公开字段含义甚至加密。因此未知 TCH 不能因能 filer-out 就被认定语义已理解；本次不解析私有 DWG filer 布局，不扫描内存偏移。未知类保留、明确不足，公开稳定业务接口另行适配。

## 建议存档边界及兼容成本

最小建议是一个独立 NOD 自有键下的 **项目有限事实伴随档案**（例如 `BCE_ELEVATION_FACTS_8D5BB4A2`；名称待实现时确定），以现有 `persistentProjectId` 关联 G2 项目。它只存上述有限事实，不建立另一套 generationId、outputs 或归属框架，也不是旁路完整历史重绑。

为什么此处不直接扩 codec：当前 `BCEPROJ1` 的固定字段顺序、版本读取和验证将 datum 与完整指纹/规则 family 关联，见 [ProjectStoreCodec.cpp:39](D:/Codex/建筑施工图自动化/立面插件/src/ProjectStoreCodec.cpp:39)、[130](D:/Codex/建筑施工图自动化/立面插件/src/ProjectStoreCodec.cpp:130)。直接放原字段不满足语义；加入 optional 字段则需新版本、双读/迁移、受限写资格设计，以及 I2 的 unit-only 判定和正式分析沿用同时调整。有限切片可通过伴随档案避开这次 G2 schema 扩展。**这是取舍建议，不证明该方案唯一或永久最优。**

不能把伴随记录放入现有 G2 自有子字典当第二条记录：现有 reader 要求其 `numEntries()==1`，否则 `PROJECT_STORE_CONFLICT`，见 [ProjectStore.cpp:75](D:/Codex/建筑施工图自动化/立面插件/src/ProjectStore.cpp:75)。伴随记录必须位于另一个自有 NOD 键，G2 `PROJECT_ARCHIVE` 原始字节、历史身份、源/输出指纹及 requiresReconfirmation 都保持。I2 继续读写原单位档案，`isUnitOnlyProject` 不放宽；本切片改变的是分析额外显示什么，不是让 G2 返回 bound。

伴随写服务只接受已重新核对的本次 context/revision、相同 persistentProjectId、该自有事实类型及所有必要 subset；不能借 `writeProjectStore` 要求的 bound 强设资格。正常 modal 命令边界下用自有事务写唯一事实记录、读回核对，任一失败 abort。沿用 G2 已证实的事务/文档锁/Undo 前置条件模式，见 [ProjectStore.cpp:80](D:/Codex/建筑施工图自动化/立面插件/src/ProjectStore.cpp:80)，不在 caller 外事务或 caller Undo group 中嵌套提交。无需为调查新增发布或权限门槛。

成本必须保留为后续工程：真正配置/BUILD 集成时，需要决定把有限记录迁入 G2 新 schema，还是由统一项目服务读取两个部分；转换时重新建立完整 ObservedScene，重新验证/提升有限事实，不能直接复制 `currentSubsetMatches` 为 `bound`。若未来一次 BUILD 同时更新配置、事实和生成归属，必须纳入同一整体事务/恢复/Undo；本切片的 standalone 事实 writer 不承担整体提交。普通保存会保存本图 NOD；任意 WBLOCK/跨图克隆传播伴随档案不是此次产品能力，不自动按文件名关联项目。

## 失效、重开与撤销

- 当前命令输入前后与落档前都核活动文档、context identity/revision、项目 ID；切文档、关文档或源编辑后拒绝本次提交，保持旧档案。不能用输入结束后的新 revision 悄悄接纳旧选择。
- 下一次分析从当前内存新读依赖；相同项目 ID 只是查找入口。源缺失、exact类/owner变化、subset定义点/文字/定位/有效可见性变化，相关点/标题事实为 stale 或 unsupported；旧记录保留供定位，不自动改成新值。隐藏源不是已核有效锚点。
- `geometrySubset` 不覆盖窗口内其它几何。其它对象编辑不能被宣称“整个视图未变”，也不必令一个没有变化的定义点事实失效。窗口四角作为用户明确范围保留；整体移动建筑后窗口不自动跟随。当前成员/空间分区变化应显示“观察成员已变化，需重新核对范围用于何事”，不得沿用“完整立面已确认”的状态，因为本切片从未授予它。
- 单位更新仍走原 I2；伴随记录保存旧比例及确认来源签名，每次分析比较当前单位。比例或确认来源改变时相关有限记录失效，不要求单位命令跨两个字典同步清除；U 恢复原单位/来源后可重新读取核对，而非恢复缓存资格。项目档案被 U 移除或 ID 不同，伴随记录是 orphan，不能关联到新项目。
- 解码仅给历史事实；重开/切回后必须新读所需 subset，历史 documentIdentity/revision 不作为当前库身份。readonly `BCE_ANALYZE` 不写 stale 标志入数据库；它只产生运行期定位结果。
- 成功配置是一个普通 modal 命令的一次自有字典事务，下一次独立 U 恢复旧事实字节；首次写入 U 恢复原 NOD 状态。只读 ANALYZE/INFO/ISSUES 仍用现有 `ACRX_CMD_NO_UNDO_MARKER`，见 [AnalysisCommands.cpp:345](D:/Codex/建筑施工图自动化/立面插件/src/AnalysisCommands.cpp:345)。本次不在绘图上建临时可见实体，也不自动保存/关闭/重开。
- 原 G2 归属不得被有限配置删除、替换、rekey 或“重新可信”。现有 standalone writer 已明确保护归属，[ProjectStore.cpp:65](D:/Codex/建筑施工图自动化/立面插件/src/ProjectStore.cpp:65)。伴随设计进一步让原 archive 字节保持；后续 BUILD 仍必须重新检查当前源/配置差异和用户手改。
