# 门窗内部编号样张（2026-11-02）

用户明确授权仅在隔离桌面的样张副本使用公开门窗编号命令 MCBH/TChWinLab。仍不使用 COM、Computer Use、其他天正业务命令或面板，不修改插件 C++、ARX、安装包。原定稿方案及已交付 v7 保持。

## 已取得的原生证据

- v142 在一层门 7F39 上试验，保存后由既有 ObjectARX 模块独立读入，公开 LIST 真实显示“门窗编号: M0927”；宽900、高2700、离地0、转角90保持。原根数量280，其余根几何保持，门自身仅增加编号显示夹点。该门初次试验沿用了旧版帮助中的样板门参数，本机版本直接进入编号输入，额外 M0927 被当成未知命令；没有将这条多余输入算作命令协议正确。后续批量按实测三步协议调用。
- v143 使用同一命令 E 选项，保存后内部“门窗编号”变空，说明删除显示也清空字段。此结果仅作能力试验，不用于交付。
- v144 首个窗口编号后的即时 CMDACTIVE 非零被错误视作命令未结束，导致一层未保存；二层批处理继续完成，但遗留 LOGFILEMODE=1，SDK只读检查以 E_LOGGING_BUSY 拒绝。未发布此候选。v145记录实际状态4是 SCRIPT 位，不能把它等同于普通命令仍待输入。改以实际空闲状态、保存文件和独立 SDK 读回来判定完成；同时每个专用批次起始和结束均设专用宿主日志模式0。
- v145 两层实际保存后 SDK 读取21/19处内部编号，全部与对应图面文字一致。22/20个门窗根保留，门窗原有夹点保持，仅各新增一个编号夹点。两处原来没有确定编号的1780洞口未擅自编号。
- 原生编号会随门窗自身显示，不能再保留重复独立文字。v146使用公开夹点的 AutoCAD STRETCH，只移动新增编号夹点到原图面编号位置，删除40个已重复的 AcDbText；19组原门号背景重新关联“门窗对象＋原背景块”，20组房间面积不变。图面编号由真实门窗对象自身显示，整体门窗根仍为 TDbOpening。
- v146保存后SDK逐项核对40个内部编号及全部公开字段，门窗原始几何和伸缩点保持；除新增编号点/40个明确删除文字之外，其余根与v7逐项相同。25/27条可见真实整体天正尺寸链、房名及房间/总面积文字保持。已查看两层全图、走廊和公卫原生渲染。

## 字体与图面边界

单独的字体试验副本中，对已编号门进行 AutoCAD EXPLODE，读到编号是 TCH_TEXT、样式 _TCH_WINDOW、纸面字高3.5，转角与门洞相同；试验随后 UNDO Back，还原原始门。没有猜写私有字段。原独立字为模型字高300、宽度0.65的AcDbText，不能声称两种字形度量完全相同。

因此最终使用门窗对象本身的天正编号样式。v146两层C0918较原字稍长，与公卫面积有轻微接触；v147仅沿各自洞口方向向下调整50模型毫米，保持默认侧和内部编号。38处其余位置保持。本次没有把50毫米或字体试验数值另定为通用自动化规则。

不声称整图历史密集位置均完成美观验收。例如原二层水吧名称与原家具/尺寸的接触仍保留。本轮只落实内部编号和对应图面显示，不代表 BCP_BUILD 已新增此功能，也不代表阶段2全量验收。

最终门禁、指纹、原生文件和清理状态以 qa-v147.json、delivery-v147.json 为准；出现失败不得将准备脚本或早期候选当作最终成功。
