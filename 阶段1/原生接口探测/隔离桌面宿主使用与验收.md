# 阶段1隔离桌面宿主：使用与验收

2026年10月29日。新增启动/监测工具仅用于阶段1验证调度；业务对象仍必须由ObjectARX C++原生接口和天正公开命令处理。工具不含COM，不注入输入，不调用SwitchDesktop、SetForegroundWindow或ShowWindow，不隐藏/关闭用户现有CAD。

## 文件

- `启动隔离桌面宿主.ps1`：常驻supervisor，参数检查、唯一run回执、native ready/quit身份核对、持续JSONL记录。
- `IsolatedCadHostNative.cs`：Win32 CreateDesktop/CreateProcess、只读窗口枚举、独立线程WinEvent消息泵、显式owned PID停止。
- `../tests/verify_isolated_host.py`：独立从原始JSONL和marker重算，不相信汇总的零值。
- `../tests/test_isolated_host_supervisor.py`：无CAD合约及反例测试。

最新无CAD机器自检结果在`隔离宿主机器自检_本地SHA与枚举修复_20261029.json`：21项PASS，含本地.NET SHA256、metadata失败不抛出、最小归属凭证先写入并保留、监测线程生命周期。真实跨桌面GUI子进程测试在`../runs/isolation-crossdesktop-machine-20261029-0957/machine-test.json`：15项PASS；14个Python合约反例测试PASS。它们**不是实际CAD静默执行通过**。

## 正常启动

根代理先创建stage1/runs下的新session目录、保存boot.scr和受信任ARX/INI。nonce为32个十六进制字符，应同时写入原生INI并传给supervisor。desktop名称固定为`CodexS1_<nonce>`，若已存在则拒绝，避免复用旧worker。

```powershell
& 'C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe' -NoProfile -ExecutionPolicy Bypass -File '<project>\阶段1\原生接口探测\启动隔离桌面宿主.ps1' -RunDirectory '<session>' -BootScriptPath '<session>\boot.scr' -AcadPath 'D:\CAD2020\AutoCAD 2020\acad.exe' -Profile 'TArch20V8' -Template '<existing acad.dwt>' -Nonce '<32hex>' -ReadyMarkerName 'quiet-worker-ready.json' -QuitMarkerName 'native.quit.done' -TimeoutSeconds 900
```

此脚本保持运行，可用exec会话低yield并poll。它先启动用户当前desktop上的WinEvent监测，再创建私有desktop和唯一acad.exe。窗口允许在私有desktop拥有正常客户区，用户输入desktop从未切换。复用现有天正profile；工具不导入/改写profile或安全设置，也不承诺AutoCAD自身初始化绝无共享配置写入。

已知天正启动【日积月累】模态提示可通过显式`-CloseOwnStartupTips`启用关闭。默认不启用。只在自身私有desktop枚举中命中own PID、类名`#32770`、标题严格等于`日积月累`，并在发消息前复核PID/线程/类名/标题，才PostMessage一次WM_CLOSE；每个HWND至多一次，逐条记录在`isolation-startup-tip-actions.jsonl`。不操作复选框，不改提示持久设置，不关闭许可、安全或未知窗体。此步骤只解除启动阻塞；业务创建仍由原生模块完成。

所有PS入口保存为UTF-8 BOM，避免Windows PowerShell5把中文白名单按ANSI误读。首次真实机器测试`isolation-crossdesktop-machine-20261029-0955`发现此编码失败，原FAIL保留；修复后新run通过。

`-RelatedProcessIds`为可选typed数组；默认已通过Get-Process收集启动前acad/tarch/tch/t20进程。外部`powershell.exe -File`不宜传逗号数组字符串，可省略；在同一PowerShell进程中`& 脚本 -RelatedProcessIds @(22448,16944)`才是数组参数写法。

原生ready、quit marker均须为UTF-8 JSON，至少有：

```json
{"nonce":"<same32hex>","session":"<session absolute path>","processId":12345}
```

`session`缺省时可用`run`；PID键也接受`pid`或`process`，出现多个PID键必须全部一致。ready名称可由`-ReadyMarkerName`指定；quit名称默认`native.quit.done`。supervisor不代替原生模块发退出命令：根代理的file queue负责原生退出，supervisor同时等有效quit和真实进程退出。

## 证据及判定

在session中生成：

- `isolation-binding.json`在进程创建前写入nonce、desktop、预期exe和session。
- `isolation-host-receipt.json`在CreateProcess后首先写最小PID/初始线程、creationFileTime、exe、命令行、nonce/desktop凭证，再计算可选源码指纹。哈希用本地.NET流/SHA256，不依赖Get-FileHash自动加载；可选metadata失败保留最小回执并继续监测。
- `isolation-user-events.jsonl`记录当前用户desktop上的foreground和窗口CREATE/DESTROY/SHOW/HIDE。非任务应用不采标题。
- `isolation-related-cad-events.jsonl`另存启动前相关CAD及同类新进程事件，便于发现多实例IPC把面板送到原CAD。
- `isolation-window-samples.jsonl`每500ms记录用户foreground/input desktop及私有desktop内own PID的窗口类、标题、可见性、客户区尺寸。
- 样本的`EnumerationDesktop/PidAtEnumeration/ThreadAtEnumeration`来自持有私有desktop句柄的EnumDesktopWindows；这才是跨桌面归属证据。从Default查询其他进程的GetThreadDesktop在本机返回ERROR_ACCESS_DENIED5，记录`ThreadDesktopKnown=false/ThreadDesktopError=5`，属于不可读取，不能误判为窗口位于错误desktop。
- `isolation-host-heartbeat.json`持续更新；`isolation-final.json`在结束清理后写入。

```powershell
python '<project>\阶段1\tests\verify_isolated_host.py' '<session>\isolation-final.json'
```

验收器从原始事件/样本重算own worker SHOW/foreground、监测desktop及native marker身份，并核源码指纹。返回0为该隔离合同PASS；返回1为FAIL；返回2为`REVIEW_REQUIRED`，表示已有相关CAD出现SHOW/foreground，须按时间与用户活动核对。不会自动把用户自行切CAD归罪于试验，也不会仅凭新worker的零事件就声称整次绝不打扰。业务图纸/天正对象/轴号结果另验。

若发生超时，只写`isolation-timeout.json`并继续监测，保留desktop句柄；不会自动kill。`isolation-supervisor.stop.json`中有正确nonce时只记停止请求，仍等原生quit/进程退出，不以停止监测掩盖仍运行的工作宿主。

## 显式停止异常的own worker

```powershell
& '<same script>' -RunDirectory '<session>' -StopOwnedWorker -ExpectedNonce '<same32hex>'
```

只有回执nonce/session/来源、实际exe、creationFileTime全匹配，并通过OpenDesktop(READOBJECTS|ENUMERATE)+EnumDesktopWindows在对应nonce私有desktop命中PID及已记初始GUI线程时，才Terminate该一个PID，并写显式停止回执。既不按进程名kill，也不递归终止其他进程；强制停止不计正常成功。若身份无法核准则拒绝。进程尚未创建窗口时此停止入口会拒绝，不能以foreign GetThreadDesktop访问失败为由绕过归属核对。

异常使supervisor本身退出时，`isolation-final.json`会标明仍在运行的owned worker；不会在catch中默认终止。根代理应先看回执及窗口状态，通过file queue原生退出，或使用上述明确停止入口。最终需等待/核对进程退出及桌面/进程句柄释放。

`只读隔离宿主恢复.ps1 -RunDirectory <session> -ExpectedNonce <nonce> -OwnedProcessId <pid> [-AttestedGuiThreadId <tid>] [-ExpectedCreationFileTime <time>]`只读查询进程exe/time、绑定desktop与窗口枚举，输出独立recovery证据。不发窗口消息，不停止进程，不补造正常启动回执，不把监测中断的旧run改成PASS。可不传线程获取候选GUI线程，但不得把恢复时看到的GUI线程虚称为CreateProcess初始线程。

可重复的无CAD实际机器测试入口为`测试隔离桌面机器宿主.ps1 -RunDirectory <new stage1/runs/machine-test>`。它只编译并创建自己的极小Win32测试GUI：错误创建时间停止必须拒绝、正确exe/time/PID/线程/desktop只停自己的helper，未知对话框必须拒绝，精确白名单测试对话框WM_CLOSE正常退出。测试helper15秒自动退出作为失败兜底；不使用可能转发到Default的现代notepad，不创建CAD，不切换desktop。
