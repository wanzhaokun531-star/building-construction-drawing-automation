## C++访问公开COM属性的桥

`inc/axboiler.h:357–360`存在两个公开声明：

```cpp
HRESULT AcAxGetIUnknownOfObject(LPUNKNOWN* ppUnk, AcDbObjectId& objId, LPDISPATCH pApp);
HRESULT AcAxGetIUnknownOfObject(LPUNKNOWN* ppUnk, AcDbObject* pObj, LPDISPATCH pApp);
```

`inc/aced.h:790–791`定义 `acedGetIDispatch`别名及 `IDispatch* acedGetIDispatch(bool bAddRef)`。SDK存在 `lib-x64/axdb.lib`，宿主存在 `axdb.dll`；实际链接和运行仍须验证。

此路线可由ObjectARX C++取得实体包装器，再通过标准 `IDispatch` 查询已公开的属性和方法。运行时需要枚举类型信息或查询实际名称，检查返回的HRESULT、VARIANT类型、是否只读及每个setter的效果。不能由历史JSON中的`Width/Text/Label`名称直接断定当前对象有同名可写属性。

另有 `inc/oleaprot.h` 的 `AcAxGetOleLinkManager()` 和 `GetIUnknown(AcDbObject*)`，其注释明确可能因没有包装器而返回NULL；`GetDocIDispatch(AcDbDatabase*)`在独立数据库不隶属文档时可能返回NULL。后台库与文档上下文的COM可用性应分别记录。

`inc-x64/acadi.h:7329–7335`的AutoCAD数据库COM接口还有 `HandleToObject(BSTR, IDispatch**)` 与 `ObjectIdToObject(LONG_PTR, IDispatch**)`。x64对象ID不可截断为32位。采用COM桥仍是C++插件实现路径，但不等同于获得天正专有C++类SDK。

## 首测建议及能力边界

1. 先加载最小ARX，检查本次天正RX类是否已注册、样本是否非代理；从冻结DWG工作副本首读建立当次基线。
2. 用一组原有墙和附属门窗作为整体克隆候选，回读RX类、几何、图层、样式与可公开的关系字段。单独clone门窗成功不证明洞口宿主关联仍正确。
3. 对文字、轴号、尺寸、图名先测试原型克隆及整体平移；再只通过实际公开且可写的字段修改一项可观测属性。平移成功不证明尺寸测点重构、轴号布局或图名编辑均可用。
4. 对 `AcDbBlockReference`采用标准2020接口读写，并检查属性子实体是否随整体变换正确移动；不可无条件二次变换属性。
5. 对跨图依赖记录映射与同名定义，另存关闭后重新打开，逐项比较。回滚测试应在独立试验事务/输出中执行，失败不污染输入。

| 类型 | 静态查证可采用的首测路径 | 仍未知的关键能力 |
|---|---|---|
| TDbWall | AcDb实体接口读取/克隆/整体变换；COM或RX动态属性探测 | 业务中线与左右厚度的明确读写、墙连接关系、脱离原型创建 |
| TDbOpening | 同上，优先连同宿主墙测试 | 宽高setter、定位参照、宿主墙洞口同步、开启类型及任意创建 |
| TDbText | 原型克隆；探测公开文字/位置/比例属性 | 真实字体继承、文字setter与定位setter的保存持久性 |
| TDbDimension2 | 原型克隆/整体变换；探测公开属性 | 各测点、分段、文本位置和关联实体的完整重建接口 |
| TDbAxisLabelSet | 原型克隆/整体变换；探测公开属性 | 轴线数据、序号、侧别及短轴线参数的完整编辑接口 |
| TDbDrawingName | 原型克隆；探测公开图名/比例属性 | 标题及比例修改后显示、字体和组成关系是否稳定 |

只有逐项运行并另存重开通过，才把矩阵相应单元标为支持。没有天正正式SDK不妨碍先做公开接口验证，但不能承诺所有类型的任意参数化创建。若动态公开接口不暴露所需的测点、宿主关系或初始化能力，应记录准确缺口并取得厂商接口支持；不炸开对象、不修改未公开私有数据、不把屏幕操作作为插件能力。
