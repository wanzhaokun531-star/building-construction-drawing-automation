# 轴号连续编号：本机公开协议与验证边界

本文件只记录阶段1公开命令合同、新探针接口及验收边界，不表示已构建或完成宿主运行。全部新增轴号必须保持TDbAxisLabelSet，不用普通块/文字替代。

## 已查证的本地合同

来源是本机TArchT20V8帮助`原生接口探测/help-extracted/03T20/T20轴网/轴号编辑.htm`、`轴网标注编辑.htm`、`轴网的概念.htm`以及安装SYS目录的acad.pgp/tchcmd.txt，不外推其他版本。

- `CPZH -> TReAxisNo`：点取需重排的左/下第一根轴号，输入新字符串（数字、字母或组合）。从该轴向右/上重排，所选轴号对象的两端同时影响。对象先前若倒排过，按其当前方向，不能只看到起号就认定左到右正确。
- `SCZH -> TDelLabel`：两角框选可重复多个框，Enter结束选择，再Y/N决定重排。上轮N路线只删站没有连续编号证明；Y能重排但不设置新起号。
- `ZHZH -> TLabelMerge`：点基准轴号，逐点其他需组合轴号，Enter结束，把多个原生集合合为一个；默认不重排，随后可TReAxisNo。
- 帮助明确I、O、Z不用于轴号，排序时跳过。Y以后的续号由高级选项及分区规则控制，未确认的AA/1A等形式不得猜定。本方案候选12行从A排除I/O/Z应是A B C D E F G H J K L M。

## 新代码接口（尚待根代理宿主实测）

`NativeAxisContinuousNumberProbe.inc`包含：

- `AxisContinuousNumberRequest { id, axis, number, pickWcs }`。
- `axisContinuousRenumber(p,doc,db,request)`返回json、commandCompleted、safeToContinue。所有实际公共grip、类型、命令/输入trace完整保留；只认实际选到目标，5100本身不是通过。允许正整数或A-Y排I/O的明确起号，不猜Y后续号。
- `axisContinuousMerge(p,doc,db,requests,vertical)`返回json、commandCompleted、safeToContinue、实际mergedAxis。输入必须是不同且顺序递增的单站两侧集合，每个8grip/4stretch。使用2020SDK的`acedCmdS`完整resbuf命令链，而非分段协程；要求N集合成为一个、完整4N伸缩点并集和6N真实站夹点不变，且只剩2个按下述v2合同判定的辅助控制点，并保护其他所有模型对象。
- 合并拾取可用实际grip，也可用4stretch端点派生的两条外侧引线段中点。跨建筑内部的中段不会被接受；无效圈重叠时不能仅靠传了点就推断选对。
- 有限入口`nativeAxisContinuousDigits/Letters/SkipIO`分别输入1/A/G，要求214件（完整原方案213加一个原生轴号集合）。G配合八站模板的字母期望G H J K L M N P，最终还须真实PDF确认。

`NativeAxisMergeTwoProbe.inc`的`nativeAxisMergeTwoProbe`依赖FourSideSeed的同库native clone helper，从seed215复制一个数字单站形成216件；两数字站放方案CDB4/CDB0真实200墙X，合并回215、再重排1。原213及另一方向种子必须保持，新库重开，最终数字仍待PDF逐圈检查。

## 窗口和证据要求

新入口/守卫调用根代理的`quietRequireIsolatedWorker()`；只有入口在几何准备后调用`quietPrepareOwnedView()`，纯编号/合并helper不改变视图，不activate、不改Visible、不做LOG、不操作天正面板，不写私有序列。root负责真实隔离宿主及前台窗口证据，代码静态没有窗口调用不能单独证明窗口问题已解决。

普通acdbEntGet轴号样本只含类、图层和字样式，没有code1或可直接解释的轴号列表。因此结构验收明确输出number_semantics=PENDING。最终须原生AcPl输出保存DWG，按每个实际圈的坐标核对真实数字/字母、两端一致、1..N/A..连续及I/O/Z不存在。不能把请求字符串、RTNORM、点数或保存成功当成编号语义。

只读核查已完成本地合同及SDK acedCmdS签名；两个host-evidence-missing RED均已确认，Python反例8项通过。尚未操作CAD、未改main/runner/旧inc，未进入阶段2。

## 合并辅助控制点合同v2

实际旧Seed运行`quiet-seed-20261029-094645-181680`中，数字模板9站删到1站后保留的6个真实站grip、4个stretch和圆半径/包围盒保持，但2个辅助控制点从首站坐标−R联合镜换为+R。旧v1失败记录保留。本机该2点距离圆心为√2R，属于辅助控制点，不是圆周切点，也不能据此断言打印编号方向。

Merge v2在执行命令前，从每个单站的实际8GP/4SP及原生包围盒独立推导两圆心与半径R。辅助控制点必须同时处于首站坐标−R，或同时处于+R；两点另一坐标必须分别等于两个靠圈侧stretch端点，Z一致。混合正负、非R距离、错误边位或Z、任意额外/缺失点都拒绝。所有单站R一致，合并后的原生包围盒严格等于各输入包围盒的并集。

合并输出先按多重集减去完整6N真实站GP，再检验剩余恰好2点属于预先声明的联合状态。另一站碰巧处于首站±R时，坐标相同仍须保留正确重数，不能把所有“非首站点”或所有未匹配点直接忽略。C++输出该政策、实际余点、符号和包围盒，Python验收器从原始数组重新推导，不信任布尔通过标记。编号TReAxisNo的原有合同仍要求全部GP严格不变，没有因这次删站观测放宽编号命令。

v2验收器22项合成反例测试通过，包含两种合法联合状态，以及混合符号、非R距离、错误边位/Z、移动圆心、丢站点、额外点、改变半径/包围盒和重复坐标计数。合成测试只证明检查器拒绝对应反例，不是实际TLabelMerge或连续编号成功证据。读取上述旧Seed的实际单站输出可独立识别R=400、联合+R；原始多站输入不适用单站合同。新增Merge/Number宿主运行仍由根代理完成，并须另取原生PDF核对两端实际圈号。
